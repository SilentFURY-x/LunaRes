# LunaRes

AI framework for enhancing low-resolution satellite and planetary imagery — built for problem statement AIML-03.

Trained on real paired low/high-resolution lunar imagery (Chandrayaan-2 TMC-2 + OHRC), with per-pixel confidence mapping and an ISRO-pipeline-compatible integration layer.

Full design docs live in [`docs/`](./docs):
- [`docs/PRD.md`](./docs/PRD.md) — what we're building and why
- [`docs/Architecture.md`](./docs/Architecture.md) — system design
- [`docs/AppFlow.md`](./docs/AppFlow.md) — screens and user journeys

- [`docs/DataSources.md`](./docs/DataSources.md) — where the training data comes from, and in what format
- [`docs/WorkingPlan.md`](./docs/WorkingPlan.md) — build order, team roles, differentiation strategy

## Repository layout

```
lunares/
├── frontend/           React + TypeScript web app (upload, map/AOI picker,
│                        tiled before/after viewer, job dashboard)
├── backend/
│   ├── api/             FastAPI app — routes, schemas, config, dependencies
│   │   └── routers/      scenes, jobs, products, pipeline, WebSocket
│   ├── services/        Centralized storage service (S3/MinIO abstraction)
│   ├── adapters/
│   │   └── bhoonidhi/    ISRO pipeline adapter (mock + live implementations
│   │                      behind one interface)
│   ├── workers/          Celery tasks — tiling, inference, mosaic blending,
│   │                      quality metrics (PSNR/SSIM/NIQE)
│   ├── models/            SR model wrapper (PyTorch + bicubic fallback)
│   │                      + uncertainty/confidence estimation
│   └── db/                 SQLAlchemy models, PostGIS schema, auto-init
├── ml/
│   ├── data/               PDS→COG normalization, TMC-2/OHRC pairing scripts
│   ├── train/                Training scripts and configs
│   └── eval/                  Metrics: PSNR/SSIM/LPIPS, no-reference quality
├── infra/
│   └── docker-compose.yml     Postgres+PostGIS, Redis, MinIO, API, worker,
│                                tile server, frontend — one command, full stack
└── docs/                        This project's PRD, architecture, and planning docs
```

## Quick start (local development)

```bash
# 1. Copy environment config and fill in any real secrets
cp .env.example .env

# 2. Bring up the full stack
cd infra
docker compose up --build

# 3. In separate terminals, once services are healthy:
#    Frontend dev server (hot reload) — optional, compose already serves a build
cd ../frontend && npm install && npm run dev

# 4. Backend API docs (auto-generated by FastAPI)
#    http://localhost:8000/docs

# 5. Frontend
#    http://localhost:5173 (dev server) or http://localhost:3000 (compose build)
```

## Where to start reading the code

- New to the project? Start with `docs/Architecture.md`, then `backend/api/main.py`.
- Working on the model? Start with `ml/data/README.md`, then `ml/train/train_sr.py`.
- Working on the pipeline integration? Start with `backend/adapters/bhoonidhi/base.py`.
- Working on the UI? Start with `frontend/src/App.tsx` and `frontend/src/pages/`.

## Data & attribution

Training data is sourced from ISRO's ISSDC/PRADAN archive (Chandrayaan-2 TMC-2 and OHRC) and NASA's PDS Imaging Node (LROC). See `docs/DataSources.md` for full access instructions and required citation text — do not omit the ISSDC acknowledgement in any published or demoed output.
